这是这个博客的第一篇文章。作为一名 ROS 初学者，我打算把学习路上的理解、实验和踩坑都记录在这里。第一篇不搞复杂的，先聊聊 ROS 到底是什么，以及三个最基础、也最容易被新手搞混的概念：**节点、话题、服务**。

## ROS 是什么

ROS（Robot Operating System）名字里虽然有"操作系统"，但它并不是 Windows、Linux 那种操作系统。它更像一套**机器人中间件**：跑在 Linux（我用的是 Ubuntu）上，帮你把一个机器人的各个程序模块组织起来、互相通信。

一个真实的机器人身上同时跑着很多程序：摄像头读图像、雷达扫障碍、电机发速度、屏幕做显示……如果它们两两直接连线，代码会乱成一团。ROS 的思路是：每个功能写成一个独立的小程序，大家通过一套统一的"通信机制"对话，互不认识也能协作。

## 三个核心概念

### 节点（Node）：一个干一件事的小程序

节点就是 ROS 里的一个进程，**一个节点只负责一件事**。比如驱动摄像头的是一个节点，让轮子转起来的是另一个节点。

这很符合 C 语言里"单一职责函数"的思路：把大问题拆成小函数，每个函数只干一件事。节点就是机器人世界里的"函数"——只不过它们各自独立运行，还可以分布在不同的机器上。

### 话题（Topic）：发布 / 订阅的广播台

话题是节点之间**单向、持续**传数据的通道，用的是"发布 / 订阅"模式：

- 发布者（Publisher）往某个话题上不停发消息，比如雷达节点往 `/scan` 发障碍物数据；
- 订阅者（Subscriber）订阅自己关心的话题，有新消息就自动收到回调。

可以类比成广播电台：电台只管发射，不关心谁在听；收音机调到对应频率就能收到。发布者和订阅者互相不认识，想加入的节点随时可以加入。

### 服务（Service）：一问一答的函数调用

服务是**双向、一次性**的通信：客户端发一个请求（Request），服务器处理后返回一个响应（Response）。

这个对学过 C 的人最好理解——**它就像一次函数调用**：你传参数进去，它返回结果给你。比如"请求地图保存一次"这种偶尔发生、需要知道结果的事，用服务就比话题合适。

简单区分：

| | 话题 Topic | 服务 Service |
|---|---|---|
| 方向 | 单向 | 双向（请求→响应） |
| 频率 | 持续不断发 | 调用一次、应答一次 |
| 类比 | 广播电台 | 打电话问问题 / 函数调用 |
| 典型场景 | 雷达数据、图像、速度指令 | 保存地图、触发拍照 |

## 动手：用小乌龟感受一下

ROS 2 自带一个经典入门工具 **turtlesim**，一只用键盘控制的小乌龟，专门用来体会上面这些概念。安装好 ROS 2 后，开两个终端：

```bash
# 终端 1：启动小乌龟窗口（这是一个节点）
ros2 run turtlesim turtlesim_node

# 终端 2：启动键盘遥控（这是另一个节点）
ros2 run turtlesim turtle_teleop_key
```

在终端 2 里按方向键，小乌龟就会动。背后发生的事是：遥控节点把速度指令发到 `/turtle1/cmd_vel` 话题，小乌龟节点订阅了这个话题，收到指令就移动。

再开第三个终端，可以"窥探"整个系统：

```bash
ros2 node list      # 查看当前有哪些节点
ros2 topic list     # 查看有哪些话题
rqt_graph           # 用图形界面看节点和话题的连接关系
```

`rqt_graph` 弹出的图里能直观看到：两个节点通过一个话题连在一起。这就是 ROS 协作方式的最小缩影。

## 小结

- ROS 不是操作系统，而是让机器人各个程序模块互相通信的中间件；
- **节点**是干活的小程序，**话题**是持续的单向广播，**服务**是一问一答的调用；
- 跑一遍 turtlesim，用 `rqt_graph` 看一眼节点关系，抽象概念立刻就具体了。
