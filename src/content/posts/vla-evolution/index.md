上周，我做了一次关于 **VLA（Vision-Language-Action，视觉语言动作模型）发展与能力演进**的分享。这篇把当时的内容重新整理了一遍，也把分享时播放的几段视频放到对应位置。

刚开始接触 VLA 时，最容易记住的是“输入图像和语言，输出动作”。但继续往下看，会发现很多问题还没回答：机器人从哪里学会动作？为什么模型能把“已经灭绝的动物”联系到恐龙玩具？能听懂指令之后，动作就一定做得好吗？换个厨房，还能不能完成原来的任务？

我在分享里主要沿着三条线来看这些工作：

- **理解任务**：模型怎样把语言、画面和已有知识联系起来？
- **执行动作**：模型怎样生成动作，又怎样交给真实机器人执行？
- **适应变化**：物体、环境或任务组合变化之后，原来的能力还剩多少？

下面选取的是各项工作的代表贡献，既不是完整的 VLA 研究史，也不是模型性能排行榜。RT、OpenVLA、π 系列和 Helix 有不同的研究背景与机器人平台，不能简单理解成一条逐代替换的产品线。

## 一、从一个抓取任务说起

先考虑一个具体任务：**把桌上的蓝色方块放进盒子。**

在模块化机器人系统中，工程师通常先组织好任务流程，再让不同模块协作完成：

1. **任务编排**：先靠近方块，再抓取、移动、放置；同时定义步骤切换和失败恢复条件。
2. **感知**：从相机画面中识别方块和盒子，估计位置或位姿。
3. **抓取与运动规划**：选择抓取方式，计算机械臂可执行、尽量避开障碍的运动。
4. **控制**：结合反馈跟踪目标轨迹，控制关节和夹爪。
5. **执行与反馈**：机器人实际操作，再检查有没有抓住、有没有放到目标位置。

![模块化机器人系统：任务编排、感知、抓取与运动规划、控制、执行，以及失败后的反馈回路](/images/vla-evolution/modular-robot-pipeline.webp)

这里的“传统”并不意味着完全不用 AI。感知可以使用深度学习，任务规划也可以使用搜索算法；系统内部还可能有多层反馈回路。

真正需要关注的是：**当任务范围扩大时，需要适配哪些环节？**

方块换成杯子，可能要调整识别、抓法和夹持方式；任务改成“先分类，再放进不同盒子”，需要重新组织任务逻辑；物体掉到原来没考虑的位置，则要检查已有恢复分支能不能处理。

已有模块当然可以覆盖一部分变化，不是每换一个物体就必须重写程序。但随着任务增多，模块、规则和接口的维护成本也会增加。这就引出了另一个思路：能不能收集不同任务的操作示范，让模型学习**根据观察和指令选择动作**？

图中的 VLA 替换范围只是教学示意。实际策略可能覆盖从感知到动作生成的多段映射，是否保留独立规划模块，要看模型和机器人的动作接口。

## 二、RT-1：从示范中学习多任务动作策略

[RT-1（2022）](https://robotics-transformer1.github.io/) 的一个重要意义，是把大量机器人示范用于训练统一的多任务策略。

### 示范数据里究竟记录了什么？

人通过遥操作完成任务，同时记录任务指令、相机画面和机器人动作。一条完整轨迹中有很多时刻，每个时刻都可以形成监督样本：

```text
输入：近期画面 + 任务指令
标签：对应时刻的人类示范动作
训练：预测动作，与示范比较，再更新模型参数
```

这属于模仿学习中的**行为克隆**。RT-1 原始工作的主要训练方式是离线学习示范动作，并非机器人从零开始，主要靠奖励在现场反复试错。

官方数据集包含超过 **13 万条操作轨迹、700 多种任务**，由 13 台机器人在 17 个月中采集。这里的“13 万条”指操作轨迹，不能直接当成图片数或训练时刻数。

### RT-1 怎样预测动作？

可以把结构概括为：

```text
近期图像 + 语言指令
        ↓
视觉特征提取，语言通过 FiLM 调节特征
        ↓
TokenLearner 压缩视觉信息
        ↓
Transformer 预测动作 token
        ↓
解码为动作数值，交给后续控制系统
```

这里的 **token 不一定是文字**。视觉 token 可以表示图像特征；动作 token 则可以表示动作数值的离散档位，例如某个方向的移动量、姿态变化或夹爪开合。

RT-1 已经有预训练的视觉、语言组件和一定的泛化能力，但不能因为它使用 Transformer，就把它理解成内部装了一个聊天大模型。

## 三、SayCan 与 RT-1：谁决定步骤，谁执行技能？

如果任务变成“从抽屉里拿出零食”，就涉及开抽屉、取物等多个技能。这里需要区分**高层技能选择**和**低层动作执行**。

[SayCan](https://say-can.github.io/) 是高层框架。它结合两类信息选择下一项技能：

- 语言模型判断：这项技能对当前任务有多大帮助？
- 技能的可行性评估：在当前状态下，这项技能有多大可能完成？

在 RT-1 接入 SayCan 的系统中，SayCan 选择技能，RT-1 根据近期画面和技能指令，连续预测动作，由控制系统驱动机器人。技能结束之后，再选择下一项技能。

**SayCan 位于 RT-1 网络之外。** 一个技能的执行通常也需要多次观察和预测，并不是调用一次 RT-1 就完成整项技能。

## 四、RT-2：把图文知识用到机器人动作里

“拿起恐龙玩具”和“拿起已经灭绝的动物”，最后可能对应相同的抓取动作，但后一句需要把“灭绝”这个概念和画面中的恐龙玩具联系起来。

[RT-2（2023）](https://robotics-transformer2.github.io/) 关注的，正是预训练视觉语言模型中的知识，怎样迁移到机器人动作预测。

### 机器人示范和图文知识怎样结合？

RT-2 以预训练视觉语言模型（VLM）为基础，在微调时混合机器人示范和原有视觉语言任务，让模型学习预测动作，同时保留图文能力。

机器人动作被表示成文本形式的离散 token。使用时，模型接收图像和指令，输出表示动作的 token，再将其解析为动作数值。

可以这样理解两类数据的作用：**图文数据帮助建立物体、概念和语义之间的联系；机器人示范帮助建立这些信息与实际动作之间的联系。**

### 能力变化体现在哪里？

RT-2 官网展示了按语义类别选物、识别符号、联系数字或国旗等案例。例如，把物品移动到字母标记处，或者把香蕉移动到 `2 + 1` 对应的数字位置。

这些演示更值得关注的地方，是指令中的知识与场景目标建立了联系。它们不等于机器人仅凭互联网知识就学会了任意新运动技能；抓取、移动等动作能力仍然依赖机器人训练数据和硬件条件。

回头对比 RT-1 与 RT-2，区别不在于“有没有 Transformer”或“能不能接收语言”：

| 比较角度       | RT-1                          | RT-2                           |
| -------------- | ----------------------------- | ------------------------------ |
| 动作策略的基础 | 视觉编码器与 Transformer 策略 | 预训练视觉语言模型             |
| 动作训练       | 主要学习机器人示范            | 机器人示范与图文任务联合微调   |
| 代表贡献       | 用多任务示范训练统一动作策略  | 把图文预训练知识迁移到动作预测 |
| 动作表示       | 离散动作 token                | 文本形式的离散动作 token       |

## 五、VLA 模型之后，还需要哪些工程步骤？

RT-2 是 VLA 概念明确成形和传播的重要里程碑，但机器人结合视觉、语言与动作的探索早于它。理解 VLA 时，也不能把模型框直接等同于整台机器人。

![VLA 从指令、观察和可选本体状态出发，经模型、动作后处理、接口对齐与控制，再通过新观察形成闭环的整体流程](/images/vla-evolution/vla-pipeline.webp)

我更倾向于把整条链路拆成三个部分来看：

**模型输入与预测。** 输入通常包括图像和任务指令，部分模型还接收本体状态、多路相机或历史帧；输出可以是一步动作，也可以是一小段动作。图中的编码和融合是概念分层，不表示每个 VLA 都有相同的独立模块。

**模型外的动作适配。** 输出要按照训练时的动作定义进行解码、反归一化，并匹配硬件接口。反归一化不一定使用均值和方差，也可能使用分位数等统计量。动作的参考系也未必是相机坐标系，需要按模型约定处理。

**控制与再次观察。** 如果动作接口需要，可以经过逆运动学、轨迹生成或规划，再由控制器执行。机器人操作后产生新的观察，供下一次推理使用。不是所有模型都需要一个显式、独立的外部规划模块。

因此，**模型输出动作，不等于直接输出电机指令。** 连续动作和离散 token 是常见的表示方式，图中的示意也不是所有方法的穷尽分类。

还要分清两种回路：

- **实时执行闭环**：观察 → 推理 → 执行 → 再观察，通常使用固定参数。
- **训练更新回路**：收集数据 → 计算训练目标 → 更新模型参数。

机器人看到操作结果后重新预测，不代表它已经在现场自动更新了模型权重。

## 六、OpenVLA：让研究者能够下载、运行和微调

[OpenVLA（2024）](https://openvla.github.io/) 的价值，可以从研究和实践的可获得性来理解：公开权重、推理代码以及训练和微调工具，让更多人能亲自运行 VLA，并研究新任务适配。

原版 OpenVLA 使用 7B 规模的模型，在约 **97 万条机器人操作轨迹**上训练。这里仍然是轨迹数量，不是图片数量。

它是独立研究工作，不是 RT-2 的开源实现。能够下载，也不意味着可以不做适配就控制任意机器人：相机输入、动作含义、归一化统计和底层接口仍要对齐。

后续的 [OpenVLA-OFT（2025）](https://openvla-oft.github.io/) 则进一步关注动作生成效率和操作表现，结合并行解码、动作分块与连续动作表示等方法。

**动作块**可以理解为一小段未来控制序列。策略预测动作块，执行其中的一段，再结合新观察继续预测；它不必等于一次生成并盲目执行整个长任务。

## 七、π 系列：动作生成、环境泛化与技能组合

π 系列适合用来继续追问：理解指令之后，机器人怎样把动作做好？换个场景，或者把学过的技能重新组合，能不能继续完成任务？

### π0：连续动作生成与灵巧操作

[π0（2024）](https://www.pi.website/blog/pi0) 通过 **Flow Matching（流匹配）**在连续动作空间中生成动作块，官方展示了专项微调后的双臂叠衣、组装纸盒等任务。

入门时可以先把它理解为：模型根据图像、语言和机器人状态等条件，生成一段连续数值动作，而不是先把每个动作维度分成有限档位，再逐一还原。

这里比较的是动作表示和生成方法。**离散 token 不意味着机械臂一定运动卡顿，连续动作也不自动保证任务成功。** 实际效果还依赖数据、训练方法、控制系统和任务适配。

另外，不能把整个 π 系列概括成同一种动作表示，例如 π0-FAST 就使用离散动作 token。

### π0.5：换到一个没见过的家

[π0.5（2025）](https://www.pi.website/blog/pi05) 的重点是新环境泛化：把学过的能力迁移到训练中未见过的家庭环境，执行收拾餐具、整理卧室和铺床等较长任务。

这不只是背景换了颜色。一个新厨房会带来物体外观、位置、布局和可操作条件的变化，模型需要在这些变化下继续决定下一步做什么。

不过，**新环境不等于任意新技能**。高层任务判断和低层动作仍然可能失败，不能把演示理解为机器人已经能可靠处理所有家庭事务。

### π0.7：组合已有技能，并接受更细致的指导

[π0.7（2026）](https://www.pi.website/blog/pi07) 进一步展示了技能组合和可引导性：结合语言指导、视觉子目标等条件，尝试训练中未见过的具体任务组合。

分享中我特别关注空气炸锅案例，因为不同指导条件会明显改变我们对结果的理解：

1. **只给整体指令**：模型会做出合理尝试，但没有完整完成任务。
2. **提供逐步语言指导**：执行表现明显改善。
3. **利用指导进一步微调高层策略**：让它自动产生语言子目标，并配合视觉子目标，得到更自主的执行。

第三阶段没有新增遥操作示范，不代表完全没有训练更新。也不能把这三个阶段合并成“第一次听到一句话，就零样本全自动成功”。

类似地，官方展示把叠衣能力迁移到另一双臂平台，也不能推广成无需适配就能控制任意新硬件。更准确的理解是：**在相应训练与指导条件下，出现了技能重组和跨机器人迁移的初步能力。**

## 八、Helix：理解与动作可以按不同节奏协作

“把桌上的杯子递给我”，既涉及理解杯子和任务，也涉及在伸手、握持、交接时持续调整动作。这两类计算并不一定需要相同的更新节奏。

[Helix（2025）](https://www.figure.ai/news/helix) 给出了一个具体实现：

| 系统 | 主要职责                                   | 原版 Helix 公布的配置    |
| ---- | ------------------------------------------ | ------------------------ |
| S2   | 理解场景和语言，形成任务相关语义           | 7B 视觉语言模型，7–9 Hz  |
| S1   | 结合最新观察、状态与语义信息，生成动作目标 | 80M 视觉运动策略，200 Hz |

两者之间传递的是**连续潜在向量**，不是一串文字步骤。S1 可以读取最新输入并结合最近的 S2 向量继续工作，不必每次动作更新都等待一次完整的 S2 推理。

这里的频率描述系统的更新节奏，不等于相机帧率，也不是所有机器人都必须达到的统一指标。

原版 Helix 输出的是上半身动作目标，包括腕部位姿、手指以及头部和躯干等目标，不能直接概括成已经控制了双腿。

“快慢脑”只是理解不同时间尺度协作的比喻，不是所有 VLA 的必备结构。SayCan 选择文字技能的高层框架，与 Helix 通过潜在向量连接并联合训练的 S2/S1，也不能混为一谈。

### Helix 02：把走路、操作和平衡放到一起

[Helix 02（2026）](https://www.figure.ai/news/helix-02) 在层级系统中加入 S0，将能力扩展到全身移动与操作协同：

- **S2** 理解任务并组织行为。
- **S1** 以 200 Hz 生成全身关节目标。
- **S0** 以 1 kHz 跟踪目标，处理平衡、接触与全身协调。

伸手会改变重心，迈步又会改变抓取的可达性。这种联系说明，操作和移动很难只作为互不影响的两件事处理。

S0 使用人类运动数据和仿真强化学习训练，再迁移到真机。这也提醒我们：VLA 系统中可以组合不同学习方法，不能把整条路线都等同于行为克隆。原版 S2/S1 的联合训练，也不能直接推出 Helix 02 的三个层级都一起反向传播。

官网有连续厨房任务演示，建议重点观察机器人如何边移动边操作、伸手时怎样协调全身。这部分可直接观看原始页面上的视频，避免把一段展示案例当成对任意家庭任务的可靠性保证。

## 九、分享之后，我更关注怎样看演示

整理这些工作时，我把看机器人演示的关注点归纳成一个问题：这段视频究竟在证明什么？

一个按指令选对物体的片段，可能体现的是语义泛化；一段叠衣视频，可能主要体现操作技能；换到陌生厨房，考验的是环境变化下的持续执行。它们都重要，但回答的问题不同。

以后再看新模型，我会优先问：

- 变化发生在物体、布局、技能，还是已有技能的组合上？训练数据覆盖了哪些部分？
- 输入的是一句整体指令，还是持续的语言指导、目标图片或人工干预？
- 展示的是基础模型，还是经过任务专项微调的版本？
- 视频有没有加速、剪辑、重置？失败率和重复试验结果是什么？
- 使用的是哪台机器人，动作接口和控制系统承担了哪些工作？

从这些问题回头看，VLA 的进展会具体很多：RT-1 展示多任务示范如何训练动作策略，RT-2 把图文知识引入动作预测，OpenVLA 降低了研究实践的门槛；π 系列继续探索动作生成、环境变化与技能组合，Helix 则展示不同时间尺度和全身控制怎样协作。

这篇是一份学习与分享记录，没有提供独立实机评测结果。接下来值得继续动手追的问题，是怎样把一个开放策略真正接到自己的机器人上：让相机输入、动作定义、反馈和控制接口逐一对应起来，再观察它在哪里成功、又在哪里失败。
